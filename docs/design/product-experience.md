# Product Experience / プロダクト体験

## Vision / ビジョン

Regapro AI は **ビジネス OS（Business OS）** です。AI チャットアプリではありません。

営業・案件管理・調査・成果物作成を、一つの作業環境で完結させます。AI は各作業の中に埋め込まれた能力であり、会話そのものがプロダクトの中心ではありません。

## Core Principles / 基本原則

### 1. Work-First, Not Chat-First / 作業優先

ユーザーが開く理由は「話す」ことではなく **仕事を進める** ことです。

- ホーム画面は「今日のタスク」「進行中案件」から始まる
- 調査結果はチャット履歴ではなく、案件コンテキストに紐づく
- 成果物（提案書、議事録）は編集可能なドキュメントとして存在する

### 2. Organize by Work Units / 作業単位で整理

ナビゲーションは **ユーザーの仕事の単位** で構成します。機能名や実装名ではありません。

| 作業単位 | ユーザーが考えること |
|---|---|
| 案件 | この商談をどう進めるか |
| 顧客 | この会社との関係はどうなっているか |
| タスク | 今日何を片付けるか |
| 調査 | この論点の根拠は何か |
| 成果物 | この提案書を仕上げる |

**UI に出してはいけない名称例:** Repository, Provider, Worker, Pipeline, Embedding

### 3. Professional, Not "AI Demo" / 業務ソフトらしさ

- 青紫グラデーション、グロー、ガラスモーフィズム、星/sparkle 装飾は使わない
- 大きな角丸カードのグリッド、巨大 KPI カード、ヒーロー的な長い説明文は使わない
- すべてをカードで包まない — テーブル、リスト、インライン編集を優先
- 同列の強いボタンを縦に並べない — 文脈ごとに Primary 1 つ

### 4. Context Over Dashboards / ダッシュボードより文脈

数値の羅列より、**今の案件で次に何をすべきか** を示す。

## Primary User Flows / 主要フロー

```
[今日] → タスクを完了 → 案件詳細へ
[案件] → 調査を開始 → ソースを確認 → 成果物下書き → レビュー → 共有
[顧客] → 履歴確認 → 新規案件作成
```

## Emotional Design / 感情設計

| 目標 | 手段 |
|---|---|
| 安心感 | 明示的な保存状態、取り消し可能な操作 |
| 効率 | キーボードショートカット、インライン編集 |
| 信頼 | 調査ソースの明示、成果物の版管理 |
| 集中 | 余計な装飾なし、コンパクトなヘッダー |

## Success Metrics / 成功指標（内部）

- タスク完了率、案件ステージ進行率
- 成果物作成〜共有までの時間
- 調査ソースの再利用率

※ これらは **コンテキスト内のインライン表示** に留め、巨大 KPI カードとしてホームに並べない。
